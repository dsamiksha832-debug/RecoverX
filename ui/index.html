HOW RECOVERX WORKS

Every file gets a way back.

RecoverX splits files into chunks, stores them by SHA-256 hash, and keeps version manifests so you can verify and restore earlier copies.

OPERATIONS / STORAGE

Create a backup

Capture the current contents as a new version in the chunk store.

◈

What happens

RecoverX reads the source in chunks, hashes each chunk with SHA-256, stores new chunk data only once, and writes a version manifest.

The source file stays in place. A new version ID appears in the result.
OPERATIONS / VERSIONS

Version history

List saved versions for a file and see each version’s integrity status.

◷

History and list

Both commands show matching versions newest first, including size, status, and chunk count.

Create at least one backup first to populate the history.
OPERATIONS / INTEGRITY

Verify integrity

Validate a saved version’s manifest and stored chunks.

✓

Integrity status

A valid version reports OK. If stored data has been altered, verification reports CORRUPT and the command returns a nonzero status.

Try this after the corruption demo to show detection.
OPERATIONS / RESTORE

Restore a version

Write one selected version to a destination file.

↙

Safe restoration

The chosen version is reconstructed from its chunks and written to the destination you specify.

Use a separate output path to keep the original sample unchanged.
OPERATIONS / RECOVERY

Auto recover

Scan versions newest first and restore the newest one that passes verification.

⟳

Automatic selection

RecoverX checks saved versions from newest to oldest, then restores the first valid version to the target file.

Recovery replaces the target file with the recovered contents.
OPERATIONS / RECOVERY

Undo latest change

Restore the newest valid version before the latest snapshot.

↶

Step back one version

Undo skips the latest snapshot and restores the newest valid earlier version to the target file.

Undo needs at least two saved versions and replaces the target file.
OPERATIONS / DEMO TOOLS

Simulate corruption

Introduce controlled damage to a stored version to demonstrate integrity checking.

⚡

Controlled simulation

Only the selected stored version is targeted. RecoverX protects chunks shared by other manifests and never changes the source during this operation.

Use a demo backup. Then verify it and run Auto recover to show the fallback.
